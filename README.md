# 日常工作簿 · Wanin Work Output

個人工作紀錄工具，使用原生 HTML / CSS / JavaScript，不需建置、不使用 AI 或付費資料庫。

## 功能

- 工作與筆記是獨立項目。輸入與清單的工作／筆記頁籤同步切換，各自保留草稿、編輯中的內容與篩選條件；重新開啟時還原上次頁籤。
- 筆記具有內容、開始／結束日期、建立與修改時間，可編輯、刪除、搜尋及匯入；沒有完成狀態或工作的備註編輯按鈕。筆記跨日同樣包含首尾日。
- 筆記自動或手動獨立輸出為 `YYYY-MM-DD_筆記.txt`，不混入兩份工作 TXT。手動輸出依目前頁籤選擇類型，筆記只有一份下載，備份則包含兩種項目。
- 紀錄以可選 kind 區分，舊版沒有 kind 的紀錄視為 work；不可把同一項目直接轉成另一種類型。請所有裝置更新至 v2026.10.30.1 再編輯，避免舊版程式無法識別筆記。


- 每筆工作自訂開始／結束日期、原文、獨立備註及完成狀態；可編輯、刪除、搜尋工作或備註、依日期與狀態篩選。備註可由清單單獨修改，不變動工作原文。
- IndexedDB 保存紀錄；本地草稿自動保存。Android Chrome 與電腦瀏覽器共用同一網址。
- Google Drive `drive.file` 最小權限配合 Picker 選取資料夾。權杖僅在記憶體中，過期及重新開啟後，按「立即同步」即可重新取得授權並沿用原資料夾；僅首次授權或資料夾存取權失效時開啟 Picker。
- 停止編輯 4 秒後同步，開啟中的網頁每 30 秒檢查更新，失敗時退避重試。網頁關閉時不執行背景同步。
- 期間含首尾兩天，每一天分別產生 `YYYY-MM-DD_完成.txt`、`YYYY-MM-DD_未完成.txt`，各自 1.、2.、3. 編號，UTF-8 / CRLF。不改寫原文；有備註時在該筆下方加入縮排的「備註：…」，多行備註繼續縮排；空狀態輸出空檔。
- 自動更新 TXT，也保留手動時間比較、上傳及本地下載備援。兩份 TXT 並非單一原子交易，部分失敗會保留狀態、於下次同步重試。
- 任意 TXT 可預覽後指定日期、狀態，整份或逐行匯入，選擇移除編號，偵測重複。支援 UTF-8、Big5、UTF-16 LE/BE。
- JSON 完整備份及合併還原（包含備註）；不包含 OAuth 設定、權杖、帳號綁定。歷史版本保留於備份中。

## 開始使用

1. 依 [設定教學](./SETUP.html) 啟用 GitHub Pages 及 Google Cloud API / OAuth。
2. 開啟 https://desperate972.github.io/WaninWorkOutput/ 。
3. 在「連線設定」填入同一 Google Cloud 專案的 Client ID、受限 API Key 及專案編號。
4. 按「連接 Google Drive」，登入並在選擇器中選取設定的資料夾。
5. 每台裝置首次使用皆需設定及授權；可把公開的 Client ID、受限 API Key、專案編號填入 config.js，省去逐台填寫。絕不可放 Client Secret 或 OAuth token。

## 同步設計與限制

工作版本以不可變的獨立 JSON 檔保存在 `_WaninWorkOutput_data` 子資料夾。每次修改帶有父版本 ID；不同裝置同時修改同一筆時產生多個末端版本，使用者必須選擇保留版本，才輸出受影響日期的 TXT。刪除同樣保存為版本；不直接刪除雲端檔案。同步時完整檢查版本關係，缺少父版本會停止輸出，留待下一次同步。

這是 Drive 檔案型、最終一致的同步，非即時資料庫。TXT 為衍生結果：同時輸出可能暫時出現舊版本或重複檔案，下次輪詢會再次比對並更新工具建立的相同日期/狀態檔案，使內容收斂；不自動刪除重複檔案。同名但非工具建立的 TXT 不會直接覆蓋，而會提示先重新命名。請不要把修改雲端 TXT 當作回寫清單；要加入外部修改請使用匯入。

本地紀錄綁定第一次連接的 Google 帳號與資料夾，避免切換帳號時洩漏或混合資料。要搬移請先備份，使用另一個 Chrome 設定檔還原並連接新位置。同一瀏覽器同一網站只允許一個分頁寫入（Web Locks）。清除網站資料前請確認已同步，或下載完整備份。離線或未取得另一台裝置最新資料時，輸出只包含目前裝置已知內容。

資料夾須保留非公開，儲存庫只放程式碼。授權只允許本工具使用的檔案；Google Drive 有可用空間和 API 用量限制。免費部署不需購買網域或啟用付費伺服器。

## 本地驗證

需要 Node.js 20 以上，無第三方套件：

```sh
npm test
npm run dev
```

開啟 http://127.0.0.1:4173 。如需測試 Google 登入，另將這個 origin 加入 OAuth 與 API Key 的允許來源。

自動測試包含編號/原文保留、日期搬移、狀態切換、並行版本、刪除衝突、備份驗證、TXT 編碼/匯入，以及模擬 Drive 的同步和輸出行為。真實帳號的授權、跨裝置及 Drive 上傳，必須完成 Google Cloud 設定後驗收。
